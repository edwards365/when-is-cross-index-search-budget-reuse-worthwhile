# E6 Faiss distance-count and latency supplement (2026-09-30)

The registered 48 Faiss graph records (24 per dataset) have complete target-role count outputs and original AVX2 single-query API latency measurements. There are 168 fixed graph/action cells and 1,000 target-evaluation queries per cell. The 24 records for each dataset contain only 13 distinct serialized graph hashes; they are not 24 independent graphs.

- The source-validated GENERIC Faiss 1.8.0 distance-computer adapter produced 2,443,776,092 target distance evaluations over 168,000 query/action responses; 75,797,778 source events were independently checked against original vectors. Target events were not independently traced. The historical original AVX2 `ndis` counter remains unavailable; the failed original probe and one monitor-cleanup failure remain in their original records.
- The original Faiss 1.8.0 AVX2 wheel yielded 840,000 timed individual `index.search(query, 10)` calls: five complete repetitions per query/action, with 8,400,000 ordered returned IDs. All raw times and returned IDs were preserved, and every response matched the sealed reference in the independent audit. All 48 native and audit stages and the external panel wait actually exited 0.
- [e6_faiss_cost_latency_v1_table.csv](../../results/icde2027_1m/e6_faiss_cost_latency_v1_table.csv) contains per-graph/action count mean/p95/p99 and original-AVX2 API latency mean/median/p95/p99. It reports the two runtimes explicitly; no count/time ratio is presented as an original-wheel measurement.
- [e6_faiss_avx2_latency_v1_closure.json](../../results/icde2027_1m/e6_faiss_avx2_latency_v1_closure.json) binds every prospective configuration, actual worker/audit wait, raw-file hash, runtime identity, sampled thread mask and panel operation file. The prior [count output closure](../../results/icde2027_1m/e6_faiss_counter_target_v1_closure.json) retains the preserved failure and full count evidence.

Timing is warm-resident, serial, fixed to query CPU4 with a separate monitor on CPU6 and one library thread. Each action used 16 ordered warmups outside the timer. The timer spans the Python single-query API call, including dispatch/allocation; index/query load, pin checks, warmups, auditing and output writes are excluded. The five repetitions are not trimmed. CPU quietness is sampled before each repetition; DVFS was not controlled and full-host exclusion is not established. These descriptive tails are neither C++-kernel-only timing, a formal confidence interval, an acquisition/lifecycle benchmark, nor a cross-algorithm deployment guarantee. All completed native DARTH/Vamana and prior Faiss scientific stages remain immutable.
