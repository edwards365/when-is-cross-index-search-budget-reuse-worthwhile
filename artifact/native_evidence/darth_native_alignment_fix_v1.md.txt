# DARTH native alignment: concrete correction, 2026-09-29

## What actually blocked progress

The failed v1-v4 compilation attempts were an additional authored synthetic
interface probe, not the DARTH native main executable. The native executable
already exists. Its presence is not proof of a successful new full-base run.
The pending v5 linker-tracing framework is not a prerequisite for using this
native path; no further expansion of that framework is planned by default.

Training source and native predictor source disagree on two pairs of columns.
The new trainer selects the following order, matching the native predictor
array instead of changing the inference algorithm:

`step,dists,inserts,first_nn_dist,nn_dist,avg_dist,furthest_dist,variance,percentile_50,percentile_25,percentile_75`

The old trainer put furthest before average and percentile_25 before
percentile_50. This is a concrete positional interface mismatch, not evidence
that the dataset cannot support DARTH. Old trainers, models, results and failed
probe receipts remain unchanged. A new model must actually be trained; editing
an old model header would not correct its learned split positions.

## Implementation delivered

`scripts/icde2027_1m/train_darth_native_aligned_v1.py` uses that explicit order,
the existing 100-tree/seed42/single-thread LightGBM schedule, finite numeric and
recall-range checks, and complete source-query coverage. It requires an ordered
query-row-ID mapping equal to the dataset's registered source_design IDs.
CSV qids are local offsets into that mapping, not raw vector IDs. It rejects
role overlap and reserves model/metadata destinations exclusively before fitting.
Partial failures remain visible; existing files are never overwritten.

The trainer verifies the declared mapping, not the actual query fvec contents or
the provenance of an observation CSV. Its metadata explicitly preserves that
limitation. The native adapter must produce those query rows and matching truth
from the registered prepared data before observation collection. There is no
hardcoded 2000-query or 100K-base requirement in this trainer.
