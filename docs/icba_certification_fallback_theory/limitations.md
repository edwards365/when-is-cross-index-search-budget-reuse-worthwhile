# Limitations and nonclaims

1. The requested server path was unavailable in this execution environment. Repository ancestry and writes use the authenticated GitHub repository; local authoring used an isolated conversation workspace rather than the absent server worktree.
2. Current experimental SHA status was read from the committed frozen audit and manifest. The 61 files were not materialized and byte-rehashed in this task.
3. The permanent legacy condition is 111/123, with eight mismatched tracked CSVs and four absent bytecode-cache entries. This closure neither repairs nor depends on those artifacts.
4. Every positive safety statement is fixed-target. Query resampling within one build supplies no outer-build guarantee.
5. Certification queries must match the deployment-query risk unit. Build count, query count, candidate count, and budget count are not interchangeable.
6. The fixed-sequence and DKW power gains require a preregistered ordered family, the same certification queries, and pointwise nested absolute failure events. Without these premises, use unstructured simultaneous control.
7. Fixed sequence is proven no more conservative than Bonferroni only for the locked monotone confidence procedure. No universal dominance over exact closed testing or every adaptive method is claimed.
8. Endpoint-censored queries are absolute failures. Therefore the maximum observed budget is not automatically a safe fallback.
9. A known-safe terminal policy is an assumption. If none exists, the only valid terminal action is abstention/no deployment.
10. Truth acquisition, retraining, probing, and control costs remain symbolic until measured in compatible units. They are never set to zero for convenience.
11. T-CF1 is a mean identity. Tail and p95 gates require separate data or separate valid bounds.
12. T-CF4 gives fixed-target query complexity, not historical-build sample complexity and not a matching minimax bound.
13. T-CF6 assumes a risk-Lipschitz graph distance. No deployable `d(G_s,G_t)` or constant is validated; Z0 and prior Z1 recovery channels failed.
14. `CERTIFIABILITY_AWARE_ORDERED_RECOVERY_TEMPLATE` is a method specification only. It is not a trained, benchmarked, confirmatory, or deployable algorithm.
15. No validation-dev or formal-test content was accessed, and no conclusion in this directory uses those sets.
