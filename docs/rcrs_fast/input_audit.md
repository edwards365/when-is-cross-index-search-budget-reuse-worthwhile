Candidate insertion, result-heap eviction and visited marking occur in a single loop. Therefore the technically plausible spike is to run from the start with fixed `e0` capacity and insert read-only checkpoint callbacks inside that loop. If stopping is disabled, a callback that only reads counters/heaps should preserve queue state, visited state, termination and fallback continuation. This must still be proven by compiled equivalence tests; changing `ef` after a smaller independent search is not prefix-preserving.
